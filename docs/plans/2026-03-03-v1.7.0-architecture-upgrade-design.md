# v1.7.0 Architecture Upgrade Design

## Overview

Upgrade the `git-collaboration-workflow` plugin to v1.7.0 with three architectural improvements:
1. Post-merge-to-main branch cleanup automation
2. Cloud review polling + auto-fix engine with Teammates architecture and local DB tracking
3. Documentation update with complete workflow diagrams

## Need 1: Post-Merge Branch Cleanup

### Problem
After a PR is squash-merged into main, the source branch (feature/hotfix) remains on remote and local, causing branch pollution.

### Solution
PostToolUse hook that detects `gh pr merge` or `git merge` completion and prompts cleanup.

### Design

**Hook type**: `command` + `prompt` (hybrid)
**Event**: PostToolUse on `Bash` tool
**Match**: Command contains `gh pr merge` or successful merge output
**Behavior**: Advisory (suggest deletion, not block)

**Cleanup scope**:
- Remote branch: `git push origin --delete <branch>`
- Local branch: `git branch -d <branch>`
- Associated worktree: `git worktree remove <path>` (if exists)

**Files**:
| File | Action |
|------|--------|
| `hooks/hooks.json` | Add PostToolUse hook entry |
| `scripts/post-merge-cleanup.sh` | New script: detect merge, suggest cleanup |

## Need 2: Cloud Review Polling + Auto-Fix Engine (Teammates Architecture)

### Problem
After creating a PR to main, the cloud code review runs on GitHub Actions (5-15 min). Currently no mechanism to:
- Track review completion
- Automatically present results locally
- Launch fix workflow
- Allow developer to continue other work while waiting

### Solution
**Teammates-based architecture**: After PR creation, spawn a `review-watcher` teammate that polls review status and handles fixes, while the main controller and developer continue other work.

### Why Teammates over Background Scripts

| 维度 | 后台脚本 + 启动新实例 | Teammates (选定方案) |
|------|----------------------|---------------------|
| 等待方式 | `poll-review.sh` shell 后台进程 | review-watcher teammate 会话内轮询 |
| 修复方式 | `launch-fix.sh` 开新 tmux 窗口 | 同一 teammate 直接修复 |
| 交互性 | 需切 tmux 窗口看修复进度 | teammate 消息自动送达主控 |
| 逻辑问题处理 | 新实例暂停等开发者切过去 | teammate 直接 SendMessage 问主控 |
| 主控端 | 不受影响 | 不受影响 |
| 成本 | 轮询零成本，修复按实例计 | idle 期间零 API 成本，唤醒时消耗 |
| 会话结束 | 后台脚本存活 | teammate 随会话结束（DB 兜底恢复） |

### Architecture

```
/create-pr 提交 PR → main
       │
       ├── 注册到 review-tracker.json (持久化)
       │
       ├── TeamCreate("review-cycle")
       │      ├── review-watcher teammate  ← 轮询 + 修复
       │      └── 主控 + 用户              ← 继续其他工作
       │
       │   review-watcher 行为：
       │   ┌─────────────────────────────────┐
       │   │ 1. 每 60s: gh pr checks         │
       │   │ 2. 审查完成 → 拉取评论          │
       │   │ 3. 代码级 → 直接修复 + push     │
       │   │ 4. 逻辑级 → SendMessage 给主控  │
       │   │    等待人类决策                  │
       │   │ 5. push 后继续轮询下一轮        │
       │   │ 6. 审查通过 → 通知主控          │
       │   │    → shutdown                   │
       │   └─────────────────────────────────┘
       │
       └── DB (review-tracker.json) 持久化状态
           └── 会话重启后 SessionStart 检测恢复
```

### State Machine

| Status | Meaning | Transition |
|--------|---------|------------|
| `pending_review` | Waiting for cloud review to complete | -> `review_done` (check completed) |
| `review_done` | Review finished, results available | -> `fixing` (has comments) or `passed` (no comments) |
| `fixing` | review-watcher teammate is fixing | -> `pending_review` (push triggers new round) |
| `passed` | Review approved, ready to merge | Terminal state |
| `closed` | PR closed/merged | Terminal state |

### DB Structure (`.claude/review-tracker.json`)

```json
{
  "prs": {
    "42": {
      "branch": "feat/user-auth",
      "status": "pending_review",
      "round": 1,
      "created_at": "2026-03-03T10:00:00Z",
      "updated_at": "2026-03-03T10:00:00Z",
      "last_check": "2026-03-03T10:05:00Z",
      "comments_count": 0
    }
  }
}
```

Note: 相比之前设计，移除了 `poll_pid` 字段（不再需要后台进程 PID 追踪）。

### review-watcher Agent (`agents/review-watcher.md`)

新增 agent，作为 teammate 被 `/create-pr` 技能 spawn：

**Agent 职责**：
1. 接收 PR 编号和分支名
2. 循环轮询 `gh pr checks`（每 60s，通过 Bash sleep）
3. 审查完成后拉取评论（`gh api`）
4. 分类评论：
   - **代码级**（语法、格式、变量、类型、命名）：直接修复
   - **逻辑级**（架构、设计、竞态、业务逻辑）：SendMessage 给主控，等待人类决策
5. 修复代码级问题 → commit + push
6. push 触发新审查轮次 → 继续轮询
7. 审查通过（无评论）→ SendMessage 通知 → 更新 DB → shutdown

**Agent 工具**：`Bash`, `Read`, `Edit`, `Write`, `Grep`, `Glob`

**Agent 模型**：`sonnet`（平衡成本和能力）

### Comment Categorization

| Category | Examples | Action |
|----------|----------|--------|
| Code-level | Uninitialized variable, indentation error, wrong type, naming convention | review-watcher 自动修复 |
| Logic-level | "This approach has race conditions", "Consider using X pattern instead" | SendMessage 给主控，等人类确认 |

### Polling Lifecycle

- Teammate spawn 后立即开始轮询
- 审查通过 → teammate shutdown（通知主控后自行退出）
- 每次 push 触发的 `synchronize` 是全新审查周期（round++ 仅做统计）
- 无最大轮次限制——每轮独立

### Session Recovery (DB 兜底)

会话意外关闭时 teammate 随之结束。恢复机制：

1. SessionStart hook 检查 `review-tracker.json`
2. 发现 `status != passed/closed` 的 PR
3. 提示用户：`"PR #X 有未完成的审查周期，运行 /check-review 查看状态或重新启动监控"`
4. `/check-review` 技能可手动查看状态 + 重新 spawn review-watcher

### Workflow Diagram Coverage

Complete development lifecycle:
```
feature branch → /review-pr self-check → push →
create PR → main → cloud code review →
review-watcher teammate polls → review complete →
code-level auto-fix by teammate → push → new review round →
logic-level issues → SendMessage to controller → human decides →
review passed → teammate notifies + shuts down →
squash merge → post-merge cleanup hook → branch deleted
```
